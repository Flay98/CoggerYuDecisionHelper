# About

The repository presents calculation of optimal alternatives in multicriteria task via Cogger and Yu method [1].

The project is completed during the Descision Making course at SPbPU Institute of Computer Science and Cybersecurity (SPbPU ICSC).

## Математическое ядро МПС

Ядро независимо от консольного приложения и не использует `Ranker.EigenValues()`.
Существующие методы ранжирования и их тесты сохранены.

- `PairwiseComparisonMatrix` — неизменяемая модель `double[n][n]`, `n >= 2`.
  Конструктор проверяет форму, конечность, положительность, диагональ и обратность.
  `size()` возвращает размерность, `get(i, j)` — элемент, `toArray()` — глубокую копию.
- `ConsistencyMetrics.principalEigenvalue(A)` — главное собственное значение.
- `ConsistencyMetrics.saatyIndex(A)` — индекс Саати CI.
- `ConsistencyMetrics.koczkodajIndex(A)` — `KoczkodajResult`: `value()` и
  `worstTriad()` типа `Optional<Triad>`. Тройка содержит `i`, `j`, `k` и
  `localInconsistency`. Индексы **с нуля**. При равных вычисленных максимумах
  выбирается первая тройка в лексикографическом порядке. Для `n = 2` принято
  `K = 0`, `worstTriad()` пуст; при `n >= 3` тройка возвращается даже при `K = 0`.

Пример использования в Java:

```java
import MCD.consistency.PairwiseComparisonMatrix;
import MCD.consistency.ConsistencyMetrics;
import MCD.consistency.KoczkodajResult;

// Внутри метода:
PairwiseComparisonMatrix matrix = new PairwiseComparisonMatrix(new double[][] {
    {1, 3, 4}, {1.0 / 3, 1, 2}, {0.25, 0.5, 1}
});
double ci = ConsistencyMetrics.saatyIndex(matrix);  // ~0.009147353645
KoczkodajResult k = ConsistencyMetrics.koczkodajIndex(matrix); // ~1/3
boolean consistent = matrix.isMultiplicativelyConsistent(1e-10); // false
```

### Формулы и численная реализация

Индекс Саати:

$$CI(A) = \frac{\lambda_{\max}(A)-n}{n-1}.$$

Используется разложение собственных значений существующей JAMA
(`EigenvalueDecomposition`). Для положительной матрицы выбирается положительное
вещественное собственное значение с наибольшей вещественной частью (корень Перрона).
Перед разложением выполняются диагональные преобразования подобия и общее
масштабирование в логарифмической области. Они сохраняют спектр с учётом известного
общего множителя и не изменяют хранимые сравнения. Это численное обусловливание,
а не алгоритм коррекции МПС.

Для индекса Кочкодая перебираются все `i < j < k`:

$$r = \frac{a_{ij}a_{jk}}{a_{ik}},\qquad
\kappa_{ijk} = \min(|1-r|, |1-1/r|) = 1-\exp(-|\log r|),\qquad
K(A) = \max_{i<j<k}\kappa_{ijk}.$$

`NumericalSupport` раскладывает числа на двоичные мантиссы и степени, поэтому
произведение коэффициентов не переполняется и не исчезает при потере порядка.
Около согласованности используются `Math.fma` и `Math.log1p`, затем `Math.expm1`.
Перебор троек требует `O(n^3)` времени и `O(1)` дополнительной памяти.

Определения индексов соответствуют источникам
[Куренных и соавт., 2018](https://doi.org/10.20948/prepr-2018-196) и
[Sayadi–Janicki, 2026](https://doi.org/10.1016/j.ijar.2026.109626).
Контрольные матрицы статьи 2026 взяты из предоставленного задания.
Исходные PDF доступны в корне проекта: [статья 2018](ipmp2555.pdf) и
[статья 2026](1-s2.0-S0888613X26000022-main.pdf).

### Допуски и ограничения

Допуск структурной проверки по умолчанию — `1e-10`:
`|a_ii - 1| <= tolerance`, `|a_ij*a_ji - 1| <= tolerance`.
Он безразмерный; нельзя принять пару маленьких необратных чисел лишь из-за
их малой абсолютной разницы. Допуск конструктора должен быть конечным и лежать
в `[0, 1)`. Некорректные данные вызывают `IllegalArgumentException` с пояснением.
Введённые значения никогда не заменяются обратными автоматически.

В исправленном примере опубликованы округлённые числа `0.7714` и `0.4881`, поэтому
он создаётся с явно указанным допуском `new PairwiseComparisonMatrix(data, 1e-4)`.
Тест отдельно проверяет вариант с обратными значениями, вычисленными по верхнему
треугольнику. K по определению использует верхний треугольник; CI использует
всю введённую матрицу, поэтому округление нижнего треугольника может влиять на CI.

`isMultiplicativelyConsistent(tolerance)` проверяет все упорядоченные тройки,
включая повторяющиеся индексы: отношение `a_ij*a_jk/a_ik` должно находиться
между `1/(1+tolerance)` и `1+tolerance`. Допуск конечный и неотрицательный.
Это приближённая идеальная согласованность, а не проверка приемлемости по статье.
Пороги `CI <= 0.1` и `K < 0.3` не входят в валидацию модели.

Небольшой отрицательный CI (до `1e-10` по модулю) приводится к нулю.
Существенно отрицательный CI вызывает `ArithmeticException`, в том числе если
слишком мягкий допуск позволил принять заметно необратную матрицу.
K математически меньше 1 для конечных положительных коэффициентов, но при
экстремальной несогласованности может округлиться до 1 в `double`.
Главное собственное значение вне диапазона `double` вызывает `ArithmeticException`;
CI вычисляется отдельно в логарифмической форме и может оставаться конечным.
При несходимости численного обусловливания за 1000 проходов также выдаётся явная
ошибка. Универсальная точность для любых плохо обусловленных данных не обещается.

## Коррекция по косинусам строк: Куренных и соавт. (2018)

Реализован независимый от интерфейса класс `CosineConsistencyCorrector`.
Основной источник — [статья](ipmp2555.pdf), DOI
[10.20948/prepr-2018-196](https://doi.org/10.20948/prepr-2018-196), печатные
страницы 8–11 (страницы 9–12 PDF). Это детерминированная конкретизация описанного
метода рекомендаций; тождественность с авторской программой на C# не заявляется.

### Соответствие статье

| Шаг статьи / рис. 1 | Реализация |
|---|---|
| Проверить ИС перед коррекцией | При `CI <= targetCi` вернуть исходную матрицу без изменений |
| Формула (9), косинусы строк | `RowCosines.compute(A)`, предварительное масштабирование строк для устойчивости |
| Упорядочить косинусы по возрастанию | Независимые пары `i < k`, диагональ исключена |
| Выбрать опорные сравнения с косинусами, близкими к 1 | Рассмотреть промежуточные `j`, отличные от `i` и `k`; конкретное правило ранжирования приведено ниже |
| Формула (10) | `newValue = a_ij * a_jk`, `delta = newValue - oldValue`; одновременно `a_ki = 1/newValue` |
| Привести оценки к шкале | Явная проверка диапазона: недопустимое предложение отклоняется целиком |
| Пересчитать ИС и проверить `ИС > 0.1` | После каждой принятой правки; стандартная цель `CI <= 0.1` |
| Сохранить результат | Неизменяемый `CosineCorrectionResult` с исходной/итоговой матрицами и историей |

В PDF найдены две неоднозначности, проверенные по изображению страниц:

- В числителе (9) напечатано `a_ik * a_ik`. Используется скалярное произведение
  **разных** строк `a_ik * a_jk`, следующее из (7)–(8), пояснений статьи и задания.
- На странице 10 для опорных сравнений перечислены `xi_ij` и `xi_ik`, хотя
  `a_ik` — исправляемый элемент. В реализации надёжность цепочки оценивается
  по двум опорным сравнениям: `xi_ij` и `xi_jk`.

### Принятые решения для однозначного выполнения

Эти правила — решения данной реализации, а не доказанные утверждения авторов:

1. Обрабатываются только пары `i < k`, чтобы не исправлять одно независимое
   сравнение дважды из-за симметрии косинусной матрицы. При равных вычисленных
   косинусах порядок лексикографический `(i, k)`.
2. Для пары промежуточные объекты ранжируются по убыванию
   `min(xi_ij, xi_jk)`, затем по возрастанию `j`. Это предпочтение наиболее
   согласованной из доступных опорных цепочек, а не выбор глобально лучшего CI.
3. Статья не задаёт числового определения близости косинуса к 1. По умолчанию
   абсолютный отсев опор выключен (`minimumSupportCosine = 0`), используется
   относительное ранжирование. Следовательно, лучшая доступная опора не обязана
   быть хорошо согласованной. При необходимости задаётся явный нижний порог,
   например `0.9`; он может сделать коррекцию невозможной.
4. Пробная матрица принимается только при
   `CI_before - CI_after > minimumCiDecrease` (по умолчанию `1e-12`). Иначе
   рассматривается следующий `j`, затем следующая пара. Пробные изменения не
   меняют текущее состояние и не попадают в историю. Это дополнительная защита
   от ухудшения, циклов и правок без измеримого эффекта.
5. После принятой правки косинусы и порядок пар вычисляются заново. Блок-схема
   явно показывает исходное упорядочивание, но не повторный расчёт косинусов;
   обновление выбрано, чтобы новые рекомендации соответствовали текущей матрице.
6. Рекомендации принимаются автоматически при прохождении проверок; экспертный
   диалог из текста статьи здесь не реализуется. Дополнительная остановка по
   близости всех косинусов к 1 не используется.

Один проход рассматривает все текущие пары и допустимые промежуточные объекты
до первого принятого исправления. Если улучшения нет, возвращается
`NO_ADMISSIBLE_IMPROVEMENT` с числами отклонений по причинам: опорные косинусы,
шкала, непредставимое произведение/обратное значение, отсутствие изменения,
недостаточное снижение CI, численная ошибка при проверке пробной матрицы.
Это отсутствие улучшения **в рамках перечисленных правил**, не доказательство
невозможности улучшить матрицу вообще.

### Параметры и результат

`CosineCorrectionOptions.defaults()` задаёт:

| Параметр | Значение | Смысл |
|---|---:|---|
| `targetCi` | 0.1 | Допустимый CI из статьи |
| `maxIterations` | 100 | Максимум принятых исправлений; наш защитный лимит |
| `minimumCiDecrease` | 1e-12 | Минимальный измеримый эффект; наш допуск |
| `minimumSupportCosine` | 0 | Опоры ранжируются без абсолютного отсева |
| `minimumComparison` | `Double.MIN_VALUE` | Нет дополнительной нижней границы шкалы |
| `maximumComparison` | `Double.MAX_VALUE` | Нет дополнительной верхней границы шкалы |

Диапазон сравнений — **непрерывный замкнутый интервал**, содержащий 1.
Например, `[1/9, 9]` ограничивает диапазон, но не навязывает дискретные значения
шкалы Саати. Проверяются исходные элементы, новое значение и его обратное.
Исходная матрица вне диапазона вызывает `IllegalArgumentException`.
Выход предложения за диапазон, переполнение/исчезновение произведения или
невозможность представить положительное конечное обратное значение приводят
к отклонению предложения. Обрезки, округления и проекции на ближайшую отметку нет.
Этот отказ отличается от неуточнённого в статье блока согласования шкал.

Статусы: `ALREADY_ACCEPTABLE`, `TARGET_REACHED`, `MAX_ITERATIONS`,
`NO_ADMISSIBLE_IMPROVEMENT`. Нулевой лимит допустим: проверяется исходный CI,
затем при необходимости коррекции сразу возвращается `MAX_ITERATIONS`.
Достижение цели последней разрешённой правкой считается успехом.

Результат содержит `original`, `corrected`, `initialCi`, `finalCi`, `initialK`,
`finalK`, параметры, статус, пояснение и неизменяемую `history`.
`iterations()` — число реально принятых правок, равное длине истории.
`changedComparisons()` — число отличающихся от исходных элементов **верхнего
треугольника на момент завершения**, без удвоения за обратные элементы.
Повторная правка одной пары не увеличивает это число автоматически; история
сохраняет каждую такую правку отдельно.

Каждая запись `Change` содержит номер итерации (с 1), индексы `i`, `k`, `via`
(с 0), старое/новое значение, дельту, косинус пары, оценку опорной цепочки и CI/K
до/после правки. По этим данным можно восстановить всю последовательность МПС.
`PairwiseComparisonMatrix.validationTolerance()` позволяет сохранять явно
выбранный структурный допуск при создании каждой исправленной матрицы.

```java
// Внутри метода, при импорте классов из MCD.consistency:
var matrix = new PairwiseComparisonMatrix(new double[][] {
    {1, 3, 1}, {1.0 / 3, 1, 2}, {1, 0.5, 1}
});
var result = new CosineConsistencyCorrector().correct(matrix);
// result.status() == TARGET_REACHED, result.iterations() == 1

// Явно ограниченный непрерывный диапазон, без округления:
var settings = new CosineCorrectionOptions(0.1, 100, 1e-12, 0, 1.0 / 9, 9);
var boundedResult = new CosineConsistencyCorrector(settings).correct(matrix);
```

### Пошаговый пример из задания

1. Для матрицы из примера выше `CI = 0.183720900490621`, `K = 5/6`.
2. Получены `xi_12 = 0.711286759159019`, `xi_13 = 0.703526470681448`,
   `xi_23 = 0.835504418211084` (здесь объекты нумеруются с единицы).
3. Минимальный косинус соответствует паре `(1, 3)`. Единственный промежуточный
   объект — 2; оценка опоры `min(xi_12, xi_23) = 0.711286759159019`.
4. `a_13_new = a_12 * a_23 = 3 * 2 = 6`, `delta_13 = 6 - 1 = 5`.
   Одновременно `a_31_new = 1/6`; остальные элементы сохраняются.
5. Новый `CI = 4.44e-16` (погрешность около нуля), `K = 0`.
   Принято одно исправление независимой пары, статус `TARGET_REACHED`.

При диапазоне `[1/3, 3]` предложение 6 отклоняется. Следующая пара `(1, 2)`
исправляется через объект 3: `a_12_new = a_13 * a_32 = 1 * 0.5 = 0.5`,
`a_21_new = 2`. Получается другая согласованная матрица; обрезки 6 до 3 нет.

### Проверки и границы воспроизведения

Тесты проверяют отсутствие правок для согласованной и уже приемлемой МПС,
аналитические косинусы, выбор пары и опоры, достижение цели, ограничения числа
правок, шкалы и опор, непредставимые предложения, детерминизм, неизменность входа
и восстановление **каждой** матрицы/индекса по истории многократной коррекции.

В статье приведена агрегированная статистика, но нет исходного набора случайных
матриц, seed и полностью определённых правил выбора опор/шкалы. Её таблица 1
на данном этапе не воспроизводится. Иллюстративная МПС 3×3 взята из задания,
а не представляется опубликованным пошаговым примером авторов.

Уменьшение CI проверяется, уменьшение K не гарантируется: K здесь дополнительная
метрика, а не критерий принятия. Сохранение исходных предпочтений оценивается
историей, но минимальное число правок или минимальная суммарная вариация не
гарантируются. Ограничения вариаций из общей постановки (4) и экспертный диалог
не реализованы. При численной ошибке исходных индексов исключение ядра
передаётся вызывающему коду; ошибки пробных матриц отражаются в причине отказа.
В худшем случае перебирается `O(n^3)` пробных цепочек на шаг, каждая требует
расчёта CI; модуль рассчитан на учебные матрицы, ускорение массовых прогонов
не относится к этому этапу.

## Количественный генетический алгоритм: Sayadi–Janicki (2026)

Реализация: `GeneticConsistencyCorrector`, источник — раздел 4.1, Algorithm 1,
страницы 7–8 [локального PDF](1-s2.0-S0888613X26000022-main.pdf), DOI
[10.1016/j.ijar.2026.109626](https://doi.org/10.1016/j.ijar.2026.109626).
Функция приспособленности — только `ConsistencyMetrics.koczkodajIndex()`.
CI вычисляется для исходной и итоговой матриц, но не участвует в отборе,
разрешении равенств, принятии мутации или остановке. Число изменённых оценок
также не является дополнительной целевой функцией.

### Представление и соответствие Algorithm 1

`GeneticChromosome` — внутренний неизменяемый массив `n*(n-1)/2` генов:
`a_01, a_02, ..., a_0(n-1), a_12, ...`. У потомков диагональ всегда равна 1,
нижние элементы вычисляются как `1/a_ij`. Массив защищён копированием.
Фактическая исходная матрица сохраняется отдельной особью, а не заменяется
декодированной копией. Допустимая погрешность её обратных элементов сохраняется
в исходной особи; у потомков обратные элементы восстанавливаются из генов.
Недиагональные элементы могут быть любыми положительными числами в заданном
непрерывном диапазоне. Диагональ входа должна быть **точно** единичной; вместо
скрытой нормализации слегка отличающаяся диагональ явно отклоняется.

| Этап статьи | Выполнение |
|---|---|
| Начальная популяция | Исходная особь плюс `P-1` попыток мутации исходной особи; каждая успешная мутация меняет один случайный ген |
| Оценивание | Вычисляется K каждой новой особи; меньший K лучше |
| Отбор 50% | Стабильная сортировка по K, выбирается лучшая половина |
| Элитизм 20% от отобранных | Лучшие особи переносятся без изменения и повторного вычисления fitness |
| Скрещивание | Остальные места заполняются потомками выбранных родителей |
| Прямой перенос 10% потомков | Эта часть потомков не мутирует |
| Мутация остальных потомков | Один случайный ген получает добавку `delta = U(-0.5, 0.5)` |
| Остановка | Лучший `K < targetK` либо выполнено `maxGenerations` новых поколений |

### Однозначные технические решения

Следующие детали уточнены для данной реализации, поскольку статья не задаёт
их полностью:

- Размеры групп: `S = floor(P/2)`, `E = max(1, floor(S/5))`, `C = P-E`,
  `D = floor(C/10)`, `M = C-D`. Требуется `P >= 2`. Сохранение хотя бы одного
  элитного представителя — дополнение для малых тестовых популяций.
  При `P=1000`: **S=500, E=100, C=900, D=90, M=810**. Таким образом, 20%
  относятся к отобранной половине, а не ко всей популяции; размеры всегда дают
  ровно P особей. Для нечётных и малых P доли приближённые, правила округления явные.
- Родители выбираются независимо и равновероятно из S отобранных особей,
  с возвращением. Один родитель может быть выбран дважды.
- Скрещивание равномерное: каждый ген целиком копируется из одного из двух
  родителей с вероятностью 1/2. Усреднения, арифметической коррекции и гибридизации
  с методом 2018 года нет. Оператор скрещивания в Algorithm 1 не конкретизирован.
- При равном K сохраняется порядок добавления особей; ни CI, ни число изменений
  не используются для разрешения равенств. Элитизм сохраняет лучший найденный K.
- `java.util.Random(seed)` создаётся заново при **каждом** вызове `correct()`.
  Воспроизводятся матрица, история, статусы и счётчики, включая повторное
  использование одного экземпляра корректора. Конструктор без параметров
  использует явный seed 0, а не системное время.
- После построения начальной популяции проверяется цель. Она считается
  поколением 0; затем допускается максимум 100 новых поколений по умолчанию.
  Поколение формируется и оценивается целиком, без досрочного выхода в середине.
  Вход с `K < targetK` возвращается сразу, оценивается только исходная особь.
- В строке `while` статьи стоит `inconsistency > 0.3`, а в тексте указан выход
  ниже порога. Согласно заданию здесь используется строгое условие **K < 0.3**;
  равенство порогу не считается успехом. При `targetK=0` эта строгая цель
  недостижима, что удобно для тестирования ограничения поколений.

### Диапазон и отказ от недопустимых мутаций

Стандартные параметры `GeneticCorrectionOptions.defaults(seed)`:
`P=1000`, `maxGenerations=100`, `targetK=0.3`, диапазон `[1/7, 7]`,
`maxMutationAttempts=64`. Для примера статьи необходимо явно задать `[1/9, 9]`:
исходные 8 и 9 не помещаются в стандартный диапазон. Весь вход, включая обратные
элементы и восстановленные из верхнего треугольника обратные значения, проверяется
до запуска. Нарушение диапазона вызывает `IllegalArgumentException`.

Каждая попытка мутации равномерно выбирает один независимый ген и добавку
`random.nextDouble()-0.5`, то есть машинный полуоткрытый интервал `[-0.5, 0.5)`.
Проверяются положительность, конечность, попадание нового и обратного значений
в замкнутый диапазон, а также фактическое отличие нового double от старого.
Недопустимое предложение отклоняется, ген и добавка выбираются заново.
После 64 неудачных попыток слот занимает неизменённый родитель/потомок.
Поэтому размер популяции сохраняется даже при отказах; такие слоты отмечены
как **failedMutations**, а не как успешные мутации. Отбор допустимых предложений
эквивалентен ограниченному rejection sampling; около границ распределение
принятых добавок условное. Обрезки, округления и замены на известный ответ нет.

Статусы:

- `ALREADY_ACCEPTABLE` — исходный K строго меньше порога, популяция не создавалась.
- `TARGET_REACHED` — цель достигнута начальной популяцией или новым поколением.
- `MAX_GENERATIONS` — исчерпан лимит новых поколений.
- `NO_ADMISSIBLE_CHANGES` — исходная популяция не может получить ни одного
  представимого изменения при заданных границах и шаге мутации (проверяется отдельно).
- `MUTATION_ATTEMPTS_EXHAUSTED` — все попытки начальных мутаций исчерпаны,
  хотя допустимое изменение существует. Это не утверждение невозможности поиска
  решения; можно изменить явно заданный лимит попыток.

### API, история и статистика

```java
// Внутри метода, при импорте классов из MCD.consistency:
var matrix = new PairwiseComparisonMatrix(new double[][] {
    {1, 2, 5, 9}, {0.5, 1, 3, 8},
    {0.2, 1.0 / 3, 1, 4}, {1.0 / 9, 0.125, 0.25, 1}
});
var settings = new GeneticCorrectionOptions(1000, 100, 0.3, 1.0 / 9, 9, 42L, 64);
var result = new GeneticConsistencyCorrector(settings).correct(matrix);
// result.best(), result.finalK(), result.finalCi(), result.history(), result.seed()
```

`GeneticCorrectionResult` содержит исходную и лучшую матрицы, начальные/конечные
K и CI, число поколений, число оценённых особей, параметры, seed, статус,
пояснение и неизменяемую историю `GenerationSummary`.
`changedComparisons()` считает отличающиеся верхние элементы относительно
исходной матрицы, без удвоения за обратные оценки.

История включает поколение 0 и по записи на каждое новое поколение. Запись
содержит лучший K, размер популяции, число перенесённых особей, немутированных
потомков, слотов мутации, успешных/неуспешных мутаций и накопленное число оценок.
Для обычного запуска `evaluatedIndividuals = P + generations*C`: элитные
особи используют сохранённый fitness, остальные оцениваются один раз.
Дубликаты тоже оцениваются и учитываются; это число вызовов функции fitness,
а не число уникальных генотипов. Расчёты CI в этот счётчик не входят.

При раннем выходе `ALREADY_ACCEPTABLE` история содержит одну запись для входа:
поколение 0, размер 1, одна оценка. Для всех сформированных популяций размер
строго равен P, даже при отказах мутаций. Нулевой лимит новых поколений всё равно
позволяет сформировать начальную популяцию и найти решение в ней.

### Тесты и ограничения

`GeneticOperatorsTest` проверяет кодирование, защиту генов, состав начальной
популяции, точность fitness, отбор, наследование при скрещивании, одногенную
мутацию, отказы и границы диапазона, элитные/потомковые доли.
`GeneticConsistencyCorrectorTest` проверяет остановки, статистику и историю,
сохранение P, ранний выход, фиксированные seed, неизменность входа и контрольную
матрицу на seed 0, 1, 42. Проверки качества не требуют совпадения с ответом авторов.

Достижение порога для любой входной матрицы или seed не гарантируется. Минимизация
K не гарантирует уменьшение CI или минимальное изменение экспертных оценок.
Равномерное скрещивание, выбор родителей, правила округления и повторных попыток
не определены в статье полностью, поэтому точное совпадение авторских двух
поколений и элементов исправленной матрицы не заявляется. Операторы работают
с непрерывным диапазоном, не с дискретными отметками шкалы. Исключения ядра при
вычислении исходного/итогового CI передаются вызывающему коду; смена решения
по CI изменила бы целевую функцию и не выполняется. Качественные Algorithm 2–4,
гибридизация и массовая экспериментальная инфраструктура не реализованы. Отдельный CLI
для существующих количественных методов описан ниже.

### Входные данные

В `examples/matrices/` находятся четыре готовых файла:
`consistent_3x3.csv`, `inconsistent_3x3.csv`, `sayadi_4x4.csv`, `sayadi_4x4.json`.

Формат определяется расширением `.csv` или `.json` без учёта регистра.
Всё читается и записывается в UTF-8. CSV — квадратная числовая матрица без
заголовков, с запятой между элементами и точкой в числах. Разрешены окружающие
пробелы, научная запись и начальный UTF-8 BOM. Кавычки/текстовые заголовки
не поддерживаются. Пустые ячейки и пустые строки, включая строки между данными,
считаются ошибкой; обычный перевод строки в конце файла допустим.

JSON содержит обязательный массив строк `matrix` и необязательную строку `name`:

```json
{
  "name": "Пример МПС",
  "matrix": [[1, 2], [0.5, 1]]
}
```

Строки вида `"2"`, логические значения и `null` вместо чисел отклоняются.
JSON читается строго: без комментариев, одинарных кавычек, повторных ключей
верхнего уровня и дополнительных данных после объекта. Неизвестные поля
метаданных игнорируются. Отсутствующее имя заменяется именем входного файла.

Читатели не дублируют математическую валидацию: квадратность, `n >= 2`,
положительность, конечность, единичная диагональ и обратность проверяются
существующим `PairwiseComparisonMatrix` с допуском по умолчанию `1e-10`.
Структурно неверный файл не поступает в алгоритмы. Дополнительные требования
конкретных алгоритмов, включая диапазон GA, остаются действующими.


JSON-пример можно передать вместо CSV через `--input examples/matrices/sayadi_4x4.json`.
**В `both` оба алгоритма получают исходную МПС независимо.** Результат одного
не используется как вход другого. Косинусный метод останавливается при
`CI <= 0.1`, GA — при `K < 0.3`; это разные показатели и разные критерии.
Поэтому исходная матрица статьи 2026 года с `CI ≈ 0.0245317` не меняется методом
2018 года, хотя её `K = 0.55` требует запуска GA. Это правильный результат.

Фактически проверенные CLI-запуски с seed 42 и стандартными лимитами:

| Вход / метод | Исходные CI / K | Итоговые CI / K | Шаги | Статус |
|---|---|---|---|---|
| `sayadi_4x4.csv`, GA | 0.024531717645 / 0.55 | 0.002952052609 / 0.237072680424 | 5 поколений | `TARGET_REACHED` |
| `inconsistent_3x3.csv`, косинусы | 0.183720900491 / 0.833333333333 | ≈0 / 0 | 1 правка | `TARGET_REACHED` |
| `inconsistent_3x3.csv`, GA | 0.183720900491 / 0.833333333333 | 0.000309721058 / 0.071944605208 | 3 поколения | `TARGET_REACHED` |

При дополнительном запуске `both` на `sayadi_4x4.csv` косинусный метод вернул
`ALREADY_ACCEPTABLE`, ноль правок и исходную матрицу; GA получил тот же результат,
что и при отдельном запуске. Все 11 файлов трёх контрольных запусков повторно
прочитаны; матрицы JSON/CSV и сохранённые CI/K сверены с математическим ядром.

### Параметры командной строки

Поддерживаются `--option value` и `--option=value`; неизвестные и повторные
параметры отклоняются.

| Параметр | Значение по умолчанию / назначение |
|---|---|
| `--input` | Обязательный путь к CSV/JSON, кроме вывода справки |
| `--method` | `both`; допустимы `cosine`, `genetic`, `both` |
| `--output-dir` | `build/results/consistency` |
| `--seed` | `0`, целое 64-битное зерно GA |
| `--mutation-mode` | `UPPER_ONLY` (по умолчанию) или `BIDIRECTIONAL` |
| `--min-comparison` | Не задан: сохраняется собственная нижняя граница каждого метода |
| `--max-comparison` | Не задан: сохраняется собственная верхняя граница каждого метода |
| `--cosine-target-ci` | `0.1` |
| `--genetic-target-k` | `0.3` |
| `--max-iterations` | `100`, максимум правок косинусного метода |
| `--max-generations` | `100`, максимум новых поколений GA |
| `--population` | `1000`, численность популяции GA |
| `--help` | Справка без чтения входа и записи результатов |

Явно заданная граница применяется к обоим методам. Без границ сохраняются
настройки существующих реализаций: косинусный метод не накладывает дополнительной
шкалы, GA использует `[1/7, 7]`. Для матрицы статьи нужно явно указать **обе**
границы `[1/9, 9]`, иначе исходные значения не пройдут проверку диапазона.
Прочие параметры существующих методов, включая минимальное снижение CI,
порог опорных косинусов и 64 попытки мутации, не меняются скрыто.

### Выходные файлы и схема JSON

CLI создаёт каталог результатов и сохраняет:

- `original_matrix.csv` — исходную МПС;
- `cosine_corrected.csv` — итог косинусного метода, если он выбран;
- `genetic_corrected.csv` — итог GA, если он выбран;
- `result.json` — полный результат по схеме версии 1.

CSV записывается через `Double.toString`, поэтому каждое значение можно
восстановить как тот же double. Числа CSV/JSON не округляются до экранных
12 значащих цифр. При повторном запуске соответствующие файлы заменяются;
остальные существующие файлы каталога не удаляются. Чтобы не смешивать старые
и новые артефакты разных методов, удобно задавать отдельный каталог запуска.
Запись поверх входного файла запрещена, в том числе через символическую ссылку.

Структура `result.json`:

```text
schemaVersion: 1
indexBase: 0
name, size, inputFile
methods: ["cosine", "genetic"]          только выбранные методы
matrix: [[...], ...]                    исходная МПС
originalMatrixCsv: "original_matrix.csv"
initialMetrics: {ci, k}
results:
  cosine:
    algorithm, status, detail
    initialMetrics: {ci, k}
    finalMetrics: {ci, k}
    parameters: {targetCi, maxIterations, minimumCiDecrease,
                 minimumSupportCosine, minimumComparison, maximumComparison}
    iterations, changedComparisons, elapsedMillis
    matrix, matrixCsv
    history: [{iteration, i, k, via, oldValue, newValue, delta,
               comparisonCosine, supportCosine, ciBefore, ciAfter, kBefore, kAfter}]
  genetic:
    algorithm, status, detail
    initialMetrics: {ci, k}
    finalMetrics: {ci, k}
    parameters: {populationSize, maxGenerations, targetK, minimumComparison,
                 maximumComparison, seed, maxMutationAttempts, mutationMode}
    seed, generations, evaluatedIndividuals, changedComparisons, elapsedMillis
    matrix, matrixCsv
    history: [{generation, bestK, populationSize, retained, unmutatedOffspring,
               mutationSlots, successfulMutations, failedMutations, evaluatedIndividuals}]
```

У невыбранного метода нет секции `results` и новый CSV для него не записывается.
Индексы истории — с нуля; номера итераций и поколений сохраняют смысл существующих
алгоритмов. `inputFile` — абсолютный нормализованный путь. Матрицы присутствуют
и в JSON, и в CSV; `matrixCsv` связывает их. `result.json` можно повторно передать
как вход: его корневое поле `matrix` содержит исходную МПС, а остальные поля
рассматриваются как метаданные. Для анализа исправленной МПС используйте её CSV.

Схема формируется явно в `ResultJson`, без автоматической сериализации внутренних
объектов Java. Алгоритмические значения при одинаковом входе, параметрах и seed
воспроизводимы. `elapsedMillis` измеряется через `System.nanoTime` и исключается
из сравнения воспроизводимости.

### JSON-зависимость и проверка

Единственная новая библиотека — **Gson 2.13.2**, локальный файл
`lib/gson-2.13.2.jar`. Он получен из
[Maven Central](https://repo.maven.apache.org/maven2/com/google/code/gson/gson/2.13.2/gson-2.13.2.jar);
версия подтверждается [официальным релизом](https://github.com/google/gson/releases/tag/gson-parent-2.13.2).
SHA-256 сверена с опубликованным файлом Maven Central:

```text
dd0ce1b55a3ed2080cb70f9c655850cda86c206862310009dcb5e5c95265a5e0
```

Проверка: `sha256sum lib/gson-2.13.2.jar`. Лицензия Apache-2.0 сохранена в
`lib/gson-LICENSE.txt`. Для развёртывания копируются проект и `lib/`; Gradle
подключает JAR как файловую зависимость и не загружает дополнительные библиотеки.
После получения Gradle Wrapper доступна сборка `./gradlew build --offline`.

Тесты в `test/MCD/consistency/cli/` проверяют чтение обоих форматов, ошибки ввода,
параметры, методы по отдельности и вместе, независимость запусков, сохранённые
метрики и истории, повторную загрузку всех матриц/JSON, точность double и seed,
воспроизводимость с исключением времени, сохранение входа и запуск `MCD.Main`.

Успешное выполнение CLI имеет код 0, в том числе при достижении алгоритмического
лимита: итоговый статус записывается в отчёт. Ошибки аргументов/данных дают код 2,
ошибки файловой системы и численных вычислений — код 1. Через Gradle ненулевой
код Java-процесса завершает задачу с ошибкой. CSV и JSON сохраняются последовательно;
при сбое записи весь набор файлов не является одной транзакцией. Массовые
эксперименты и связь исправленных МПС с ранжированием альтернатив не добавлены.

## Воспроизведение доступных результатов статей

```bash
./gradlew clean build
./gradlew reproduceArticles
```

Подготовлен ограниченный фиксированный план: пример 2026 года на seed
`0,1,2,3,4,5,10,42,100,2026` для двух режимов GA и три **собственные** матрицы
для независимой проверки косинусного метода. Все параметры и оба индекса
сохраняются; выходные матрицы повторно проверяются. Результаты находятся в
`experiments/reproduction/outputs/`, таблицы — в `experiments/reproduction/summary/`.
Эталоны публикаций отделены в `reference/` и закреплены SHA-256; генератор
результатов их не перезаписывает. Подробное сопоставление оригинальных PDF,
принятые решения, источники и ограничения:
[experiments/reproduction/README.md](experiments/reproduction/README.md).

В Algorithm 1 указано `i != j`. Поэтому добавлен явный режим `BIDIRECTIONAL`:
выбирается ориентация сравнения, при выборе нижнего элемента добавка применяется
к нему, затем верхний восстанавливается обратным. Хромосома по-прежнему хранит
только верхний треугольник. Формула для верхнего гена в нижней ориентации —
`g_new = g/(1+g*delta)`, что не эквивалентно `g+delta`.
Старый режим `UPPER_ONLY` остаётся по умолчанию и сохраняет прежние результаты seed.
В CLI режим задаётся `--mutation-mode BIDIRECTIONAL` и сохраняется в JSON
как `parameters.mutationMode` (добавочное поле схемы версии 1).

Статья 2018 года содержит агрегированную статистику, но не исходные матрицы
и seed. Поэтому точное воспроизведение её таблицы 1 не заявляется; наши
иллюстративные проверки явно помечены как независимые, а не авторские данные.
