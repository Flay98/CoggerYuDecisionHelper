# Воспроизведение доступных результатов статей

Это экспериментальная верификация существующих количественных методов, а не
массовое сравнительное исследование. План зафиксирован до получения результатов:
одна опубликованная входная МПС, десять seed для каждого из двух режимов GA,
три собственные матрицы для независимой проверки метода 2018 года.

## Запуск

Из корня проекта, Java 17:

```bash
./gradlew clean build
./gradlew reproduceArticles
```

Файлы вручную готовить не требуется. Повторный запуск заменяет только результаты
в `outputs/` и сводки в `summary/`. Gradle `clean` их не удаляет. На этапе чтения
проверяются контрольные суммы эталонов; ссылки из выходных деревьев в защищённые
входы/эталоны отклоняются. `inputs/` и `reference/` не используются для записи.
Проверка ловит случайную подмену данных; она не является защитой от человека,
который намеренно одновременно меняет исходники, хеши и тесты.

Для отдельного запуска нового режима через CLI:

```bash
./gradlew runConsistency --args="--input experiments/reproduction/inputs/published/sayadi_4x4.csv --method genetic --mutation-mode BIDIRECTIONAL --seed 42 --min-comparison 0.1111111111111111 --max-comparison 9 --output-dir build/results/bidirectional"
```

## Исходные публикации и происхождение данных

Изучены оригинальные локальные PDF, не только README проекта:

- Куренных А. Е. и соавт. (2018), DOI `10.20948/prepr-2018-196`,
  [PDF](../../ipmp2555.pdf). Формулы (9)–(10) и описание: печатные страницы 8–10,
  блок-схема: 11, таблица 1: 12 (из-за дополнительного начального листа номера
  страниц PDF на единицу больше).
- Sayadi–Janicki (2026), DOI `10.1016/j.ijar.2026.109626`, раздел 4.1,
  Algorithm 1 и пример: страницы 7–8. Локальный файл в корне репозитория:
  [PDF](../../1-s2.0-S0888613X26000022-main.pdf).

Контрольные суммы PDF, страницы и доступность исходных данных записаны в
`reference/sources.json`. PDF нужны для научной проверки происхождения, но не
для выполнения готового вычислительного плана. Их не требуется скачивать при запуске.

```text

inputs/own/illustrative_3x3.csv      НАШ пример из задания, не авторский
inputs/own/cyclic_3x3.csv            НАША циклическая МПС
inputs/own/perturbed_4x4.csv         НАША МПС из весов (8,4,2,1) с заменой a_13=4 на 0.5
reference/sayadi_2026_corrected.json опубликованная исправленная МПС, не результат GA
reference/kurennykh_2018_table1.csv  ручная транскрипция агрегированной таблицы авторов
reference/sources.json              источники и ограничения доступных сведений
outputs/2026/UPPER_ONLY/seed_*/     наши результаты исходного режима
outputs/2026/BIDIRECTIONAL/seed_*/  наши результаты нового режима
outputs/2018_own/*/                 независимые проверки на наших матрицах
```

Все напечатанные верхние элементы примера 2026 года перенесены буквально.
`1/3` и `1/9` во входных CSV представлены ближайшими double. В исправленной
матрице сохранены именно `0.7714` и `0.4881`, а не заново вычисленные обратные.
Она проверяется с явно заданным допуском `1e-4` из-за округления публикации.
Её нельзя автоматически использовать вместо входа GA: перед каждым запуском
передаётся только `inputs/published/sayadi_4x4.csv`.

| Метод / операция | Статья | Наша реализация и возможное влияние |
|---|---|---|
| 2018: косинусы строк | Формулы (7)–(9), коллинеарность согласованных строк | Используется обычное скалярное произведение разных строк. В напечатанном числителе (9) повторён `a_ik`; это противоречит (7)–(8) и свойствам косинуса |
| 2018: приоритет сравнений | Косинусы по возрастанию | Только независимые пары `i<k`; равенства разрешаются по индексам |
| 2018: исправление | Формула (10), `a_ik_new=a_ij*a_jk` | Та же формула, обратный элемент обновляется одновременно |
| 2018: выбор опоры | Рекомендация выбирать близкие к единице косинусы; индексы на странице 10 неоднозначны | Максимизируется `min(xi_ij,xi_jk)`, затем индекс j. Числового отсева опор по умолчанию нет; это наше уточнение |
| 2018: последовательность | Блок-схема задаёт начальное упорядочивание и исправления | После принятой правки косинусы пересчитываются; принимается только снижение CI более `1e-12`. Это дополнения, способные изменить траекторию |
| 2018: остановка | CI не больше 0.1; опционально все косинусы близки к 1 | CI<=0.1, защитный лимит 100 правок, явный статус при отсутствии улучшения. Опциональная цель всех косинусов не реализована |
| 2018: ограничения и эксперт | Шкала S, ограничения вариаций из (4), эксперт может принять/отвергнуть рекомендацию | Экспертный диалог, оптимизация числа правок, ограничения отдельных/суммарных вариаций не реализованы. В этом плане используется непрерывный неограниченный диапазон модели |
| 2026: fitness | Индекс Кочкодая | Существующий K ядра, без CI или числа изменений в fitness |
| 2026: начальная популяция | 1000 матриц, мутация одного элемента исходной | Исходная особь сохранена; остальные P-1 слотов — одногенные мутации исходной, при отказе — неизменённая особь |
| 2026: отбор и элита | Лучшие 50%, 20% лучших из отобранных | S=floor(P/2), E=max(1,floor(S/5)); при P=1000 S=500, E=100. Дополнение min=1 относится к малым тестовым популяциям |
| 2026: потомки | 90% поколения через скрещивание; 10% потомков без мутации | 900 потомков, из них 90 без мутации и 810 со слотом мутации. Размер всегда 1000 |
| 2026: скрещивание | Конкретный оператор не определён | Равномерное наследование целых генов; родители равномерно выбираются с возвращением. Это наше уточнение |
| 2026: мутация | Случайные i!=j, добавка из [-0.5,0.5], восстановление обратного | `UPPER_ONLY` ограничивает i<j; `BIDIRECTIONAL` выбирает любую ориентацию. Различие установлено, подробности ниже |
| 2026: границы | Указана проверка допустимого диапазона; первоначально [1/7,7], но пример содержит 8 и 9 | Для примера явно [1/9,9]. Отказ/пересэмплирование ограничены 64 попытками, без обрезки. Правило отказа в статье не определено полностью |
| 2026: остановка | Текст говорит «ниже порога», псевдокод while использует `>0.3` | Сохранено требование проекта K<0.3; максимум 100 новых поколений после поколения 0. Равенство не считается успехом |

Совпадение вычисленных K у фиксированных матриц подтверждает вычисление индекса,
но не полную эквивалентность программ авторов и нашей реализации.

## Ориентация мутации: установленное математическое отличие

В PDF на странице 7 явно указано `i != j`, ограничения `i < j` нет.
При хранении верхнего гена `g=a_ij`:

- `UPPER_ONLY`: `g_new = g + delta`.
- При выборе нижней ориентации: сначала `a_ji_new = a_ji + delta`, затем
  `g_new = 1/a_ji_new`. Для строго обратной пары это `g/(1+g*delta)`.

Например, g=4, delta=0.25 даёт 4.25 при мутации верхнего элемента и 2 при
мутации нижнего (0.25+0.25=0.5). Распределения преобразований не эквивалентны.
`BIDIRECTIONAL` равномерно выбирает независимую пару и с вероятностью 1/2
ориентацию; это равномерный выбор упорядоченной пары i!=j до проверки границ.
При выбранном нижнем элементе меняется его фактическое значение, в том числе
округление, принятое в исходной матрице; затем восстанавливается верхний ген.

По умолчанию оставлен `UPPER_ONLY`. В нём не добавлено ни одного случайного
вызова, поэтому старый seed=42 сохраняет K=0.23707268042400265 за 5 поколений.
Режим записан в `parameters.mutationMode` каждого `result.json`, метаданных плана
и сводных строках. Одновременно не менялись fitness, скрещивание и доли групп.

У `BIDIRECTIONAL` появляется дополнительный вызов RNG для ориентации. Поэтому
одинаковые seed двух режимов **не** означают совпадения остальных случайных
величин по шагам. Разность результатов режимов не является изолированной оценкой
причинного эффекта одной ориентации при полностью одинаковой случайной трассе.

Есть и условный строгий вывод: в нашей схеме `UPPER_ONLY`, где начальная особь
мутирована не более одного раза, после двух новых поколений значение a_34=4
может уменьшиться максимум на 3*0.5=1.5. Равномерное скрещивание наследует ген,
а не складывает изменения родителей. Поэтому напечатанное a_34=2.0488 нельзя
получить **этим оператором и этим счётом поколений** за два новых поколения.
Это не запрещает достичь K<0.3 за два поколения с другой матрицей.
При нижней мутации изменение a_43 примерно с 0.25 до 0.4881 (дельта около
0.2381) допустимо и даёт верхнее значение около 2.0488. Мы не утверждаем,
что авторы действительно выполнили именно эту мутацию: их трасса не опубликована.

## Контроль публикации 2026 года

Два фиксированных опубликованных ориентира:

| Матрица | Опубликованный K | Независимая проверка |
|---|---:|---|
| Исходная | 0.55 | Максимальная тройка (1,3,4): 1-9/(5*4)=0.55 |
| Исправленная | 0.2317 | Максимальная тройка (2,3,4): 1-(3*2.0488)/8=0.2317 |

Независимая программная проверка перебирает тройки прямой формулой с
`BigDecimal`, DECIMAL128, без логарифмической арифметики ядра. Она используется
только для эталонов, не как альтернативный fitness.
CI обеих матриц вычисляется нами: статья не приводит соответствующие CI.
По верхним треугольникам видно 2 изменённых сравнения. Это число выведено из
напечатанных матриц, не выдано за отдельно опубликованную статистику.

Заранее заданы seed: **0,1,2,3,4,5,10,42,100,2026**. Для каждого режима
выполняются все десять, включая возможные неудачи. Настройки каждого:
P=1000, maxGenerations=100, targetK=0.3, [1/9,9], 64 попытки мутации.
Никакие значения опубликованной исправленной матрицы не передаются GA.

Таблицы `summary/ga_runs.csv` и `.json` содержат все показатели, параметры,
идентификаторы, хеш входа, статус, число изменений, время, разности к авторским
K=0.2317, двум поколениям и двум изменениям. Разности могут быть отрицательными;
авторский результат не считается оптимумом. `ga_mode_summary.*` содержит
успешность, min/median/max/mean поколений, min/mean/max K и средние CI/изменения/время.
Знаменатель успешности включает все seed, а не только удачные.

Полученный фиксированный набор результатов приведён полностью в
[summary/report.md](summary/report.md), без исключения запусков:

| Режим | Достигли K<0.3 | Новых поколений min / mean / max | Средний K | Среднее число изменений |
|---|---:|---|---:|---:|
| UPPER_ONLY | 10/10 | 4 / 5.3 / 6 | 0.266369612241 | 4.1 |
| BIDIRECTIONAL | 10/10 | 1 / 1.0 / 1 | 0.219124273724 | 2.5 |

Seed 42: старый режим — K=0.237072680424 за 5 новых поколений, 5 изменений;
новый — K=0.217337100419 за 1 новое поколение, 2 изменения. Это наблюдения
на одной конкретной МПС и десяти фиксированных seed, а не доказательство
превосходства на других матрицах. В новом режиме одно новое поколение после
начального означает два состояния популяции. Неясно, включали ли авторы
начальную популяцию в их число 2: приписывать совпадение счёта без трассы нельзя.

## Что доступно для статьи 2018 года

В публикации есть общая МПС (символьная), числовой пример проблемы шкалы
2*5=10 и таблица 1. Полных конкретных исходных/исправленных числовых МПС,
seed, точного генератора и набора из 1000 матриц нет. Таблица 1 сообщает средние
время, сумму квадратов отклонений, вариацию, итерации, изменение CI и число
изменений ранга для размеров 3–10. Например, для 3×3: 0.276 мс, 14.754,
41.328%, 1.507, 0.104, 100; для 10×10: 53.328 мс, 448.334, 127.737%,
38.434, 0.728, 283. Все строки перенесены в отдельный read-only эталон.

**Точное численное воспроизведение таблицы 1 невозможно по доступным данным.**
Вместо него проводятся три явно независимые проверки на собственных входах.
Они не сравниваются со средними авторов как одинаковые эксперименты.

Для `K2018_OWN_ILLUSTRATIVE_3` проверяется ранее заданный пример:
CI=0.183720900491 приблизительно, одна правка a_13=3*2=6, итоговый CI около нуля.
Это наш учебный пример, не авторский. `K2018_OWN_CYCLIC_3` содержит цикл
предпочтений; `K2018_OWN_PERTURBED_4` — наша согласованная матрица с одной
сознательно изменённой независимой оценкой. Все входы статические и доступны
в репозитории; генератор случайных синтетических наборов здесь не используется.

## Сохраняемые файлы и проверка

У каждого запуска ID: `SJ2026_<MODE>_SEED_<seed>` либо один из `K2018_OWN_*`.
В его каталоге находятся `original_matrix.csv`, исправленный CSV, `result.json`
и `experiment.json` (ID, происхождение, вход, хеш, путь результата).
`result.json` содержит полные параметры, начальные/конечные CI/K и историю.

В `summary/` создаются:

- `reference_checks.json` — опубликованные числа, K ядра, независимый K,
  вычисленные CI, допуск и происхождение числа изменений;
- `run_manifest.json` — фиксированный план, ID, хеши входов/эталонов, Java/ОС;
- `ga_runs.csv`, `ga_runs.json` — все 20 запусков и расхождения;
- `ga_mode_summary.csv`, `ga_mode_summary.json` — раздельные сводки режимов;
- `cosine_own_runs.csv`, `cosine_own_runs.json` — три собственных проверки;
- `report.md` — читаемые таблицы для будущего отчёта, с разделением источников.

Каждый результат после сохранения повторно читается. Проверяются структура МПС,
исходная матрица, одинаковые double в CSV/JSON, повторный расчёт CI и K, число
изменённых пар и длина истории. Для GA не требуется снижение CI, для косинусного
метода — снижение K. Ошибка проверки завершает Gradle-задачу с ошибкой.

Время зависит от JIT, порядка запуска и оборудования, поэтому оно не входит в
проверку идентичности и не сравнивается с авторами. Старые абсолютные пути
`inputFile` в результатах отражают место конкретного запуска; переносимые
относительные пути и хеши сохранены отдельно в метаданных и сводках.

Отличия скрещивания, границ, интерпретации опор и счёта поколений — возможные
причины расхождений, а отсутствие авторских seed/трасс не позволяет количественно
приписать им разницу. Достижение того же порога не является доказательством полной
эквивалентности реализаций. Графики, массовая статистика по размерностям,
качественные алгоритмы, LaTeX и презентация не входят в этот этап.
