# Собственное сравнительное исследование МПС

Этап 6 сравнивает косинусную коррекцию и GA `UPPER_ONLY`/`BIDIRECTIONAL` на
**одних и тех же входных матрицах**, независимо. Это собственная выборка,
не авторские данные. Алгоритмы и математическое ядро на этом этапе не изменены.
Научные эталоны и результаты этапа 5 находятся отдельно в `../reproduction`.

Основной результат: [аналитический отчёт](summary/report.md),
[полная таблица запусков REPORT](summary/REPORT/runs.csv),
[агрегаты](summary/REPORT/aggregated.csv),
[графики и их источники](figures/REPORT/manifest.json).

## Запуск

Требования к Java прежние: JDK 17 и Gradle Wrapper. Java-библиотеки не добавлены.
Для графиков нужны Python 3.12, matplotlib 3.10.8 и numpy 2.3.5.
Фиксированы также транзитивные версии в `scripts/requirements-lock.txt`.
Они устанавливаются с PyPI только в отдельное окружение, не в Java-зависимости:

```bash
# На чистой Ubuntu для создания venv может понадобиться python3-venv.
python3 -m venv experiments/comparison/.venv
experiments/comparison/.venv/bin/python -m pip install -r experiments/comparison/scripts/requirements-lock.txt
./gradlew clean build
./gradlew reproduceArticles
./gradlew benchmarkSmoke
./gradlew benchmarkPilot
# Сначала оцените summary/PILOT/resource_estimate.json, затем запускайте REPORT.
./gradlew benchmarkReport
```

При выполнении этого этапа системный Python не имел ensurepip: venv создан с
`--without-pip`, pip 25.3 установлен через официальный `bootstrap.pypa.io/get-pip.py`.
Это особенность данного окружения; стандартная команда выше предпочтительна.
Каталог `.venv` не входит в Git. Gradle использует его Python, если он существует,
иначе `python3`; отсутствие matplotlib даёт явную ошибку построения графиков.

Повторное построение **только графиков и аналитического отчёта**, без оптимизации:

```bash
experiments/comparison/.venv/bin/python experiments/comparison/scripts/plot_results.py
# По умолчанию REPORT. Также можно --profile SMOKE или PILOT.
./gradlew plotReport
# Повторно прочитать все сохранённые матрицы и пересчитать показатели в Java:
./gradlew verifyComparison
```

`benchmarkSmoke`/`benchmarkReport` включают Java-расчёт и графики.
`runBenchmarkSmoke`/`runBenchmarkReport` выполняют только Java-часть.
`benchmarkPilot` запускает пилот и оценку ресурсов без графиков.
`benchmarkFull` — необязательный тяжёлый профиль, **автоматически не выполнялся**.
Обычные `build`/`test` не зависят от этих задач. В IntelliJ можно запустить
`MCD.consistency.experiments.BenchmarkRunner` с аргументом `REPORT` и рабочей
директорией корня проекта; второй необязательный аргумент задаёт отдельный корень
экспериментов с собственным каталогом `config`.

## Планы и фактически выполненный объём

Все планы лежат в `config`, master seed **20261123**. У каждого размера представлены
оба типа матриц. Число запусков = N × (1 + 2 × число seed GA).

| Профиль | n | Матриц на тип/n | N входов | GA seed | P / G / лимит косинусов | Измеряемых запусков | Прогрев |
|---|---|---:|---:|---|---|---:|---:|
| SMOKE | 3, 5 | 1 | 4 | 42 | 40 / 5 / 10 | 12 | 3 |
| PILOT | 3, 6, 10 | 1 | 6 | 42 | 1000 / 100 / 100 | 18 | 6 |
| REPORT | 3–10 | 4 | 64 | 0, 42, 2026 | 1000 / 100 / 100 | 448 | 6 |
| FULL, необязательный | 3–10 | 10 | 160 | 0, 1, 10, 42, 2026 | 1000 / 100 / 100 | 1760 | 6 |

SMOKE, PILOT и REPORT фактически выполнены. Результаты этих профилей отделены;
SMOKE с уменьшенными параметрами не входит в основной отчёт. REPORT содержит
64 запуска косинусов и по 192 запуска каждого режима GA. В основной выборке
нет выборочного прекращения или удаления неудачных результатов.

Перед REPORT сохранён `REPORT.initial.json`. Пилот занял 4.405 с; консервативная
проекция — 972.686 с и около 23 МБ, что укладывалось в бюджет 1800 с/512 МиБ.
`REPORT.decision.json` фиксирует решение **до** наблюдения REPORT оставить
первоначальный план без уменьшения. Хеши первоначального и окончательного
файлов совпадают. Фактическое время Java REPORT — 86.346 с; запуск Gradle с
графиками занял примерно 95 с. Графики не входят во время алгоритмов.
FULL не выполнялся и его результаты нигде не заявлены.

Бюджеты времени профилей: SMOKE 120 с, PILOT 300 с, REPORT 1800 с, FULL 7200 с.
Отдельный математический запуск ограничен 30 с в SMOKE и 120 с в остальных
профилях. Java heap ограничен 512 МиБ; контроль объёма выходов — 512 МиБ на план.
Исключение или превышение бюджета завершает всё задание явной ошибкой с
`failure.json` и `FAILED` manifest. Незавершённые профили не строят графики и
не считаются основными результатами. Статусы алгоритма `MAX_GENERATIONS`,
`MAX_ITERATIONS` и отсутствие допустимого улучшения являются измеренными
исходами, включёнными в общую статистику, а не ошибкой инфраструктуры.

## Генерация входов

Тип **A / DISCRETE_EXPERT**: каждый верхний элемент независимо равномерно
выбирается через `java.util.Random.nextInt(17)` из
`{1/9,1/8,…,1/2,1,2,…,9}`. Диагональ 1, нижний элемент — точное вычисление
`1/upper` в double. Матрицы не фильтруются по CI/K.

Тип **B / PERTURBED_CONSISTENT**:

1. Для каждого объекта `w_i = exp(U[0, ln(3)))`; базовая МПС `w_i/w_j`
   имеет отношения в `[1/3,3]` и согласована с погрешностью double.
2. Fisher–Yates перемешивает все m=n(n−1)/2 независимых пар, выбираются первые
   `ceil(0.4*m)` — равномерное подмножество без возвращения.
3. Для каждой выбранной пары применяется `a_ij * exp(epsilon)`, где
   `epsilon ~ U[−ln(3),ln(3))`. Значение и его обратное должны принадлежать
   `[1/9,9]`, быть конечными и отличаться от исходного.
4. Недопустимая попытка отклоняется, до 64 повторов; исчерпание — явная ошибка,
   а не обрезка/округление/пропуск. Веса и все принятые возмущения сохраняются.

Каждый вход имеет ID `A_n06_m000` или `B_n06_m000`. Seed генерации определяется
только master seed, типом, n и номером образца через SplitMix64 finalizer
(точные константы/битовые поля — `MatrixGenerator.seed`). Общий изменяемый RNG
между матрицами не используется. Отдельный warmup имеет зарезервированный ID
и соль seed. При одинаковом плане матрицы воспроизводимы, включая double CSV.

Входы создаются однократно в `inputs/<PROFILE>`. При повторном запуске
проверяются спецификация, SHA-256 и CI/K, после чего читаются прежние файлы.
Их изменение вызывает ошибку. Для изменения параметров генерации используйте
новый корень эксперимента, сохраняя предыдущую выборку.

## Измерения и статистика

Общие границы `[1/9,9]`. Косинусы: CI≤0.1, минимальное улучшение CI `1e-12`,
минимальный опорный косинус 0. GA: K<0.3, 64 попытки мутации. Остальные
операторы, пропорции популяции и режимы мутации существующих классов сохранены.
Оба режима получают одинаковые значения seed, но не обязаны проходить
одинаковую последовательность случайных операций.

Прогрев — отдельные запуски всех конфигураций в той же JVM/рабочем потоке;
для REPORT заранее выбран тип A, n=6. Порядок трёх конфигураций циклически
сдвигается по номеру входа, порядок seed тоже. Размерности идут по плану.
Время берётся из существующего `AnalysisRunner`, измеряющего только вызов
корректора: чтение, вычисление исследовательского D, экспорт и графики исключены.
Нет параллельных измеряемых оптимизаций. Среда Java/ОС/CPU/RAM/heap сохраняется.
Ограниченный прогрев не устраняет все эффекты JIT/GC; это прикладное измерение
данной машины, не универсальная оценка сложности и не JMH.

Каждая итоговая матрица повторно читается через `PairwiseComparisonMatrix`;
`SavedResultVerifier` независимо пересчитывает CI/K и сверяет JSON, CSV,
число изменений и длину истории. Проверяется SHA исходного файла перед каждым
методом. Исходная МПС не меняется и не подменяется результатом другого метода.

Дополнительные диагностические показатели:

- `deltaCi/K = initial − final`; отрицательное значение остаётся в данных.
- `relativeCi/K`: относительное изменение, `null`/`NA` при исходном ≤`1e-12`.
- `D = sqrt(mean((ln(b_ij/a_ij))²))`, только i<j. Вычисляется через разность
  логарифмов (без переполнения отношения), `log1p` для близких значений и `hypot`
  для устойчивой суммы квадратов. D не включён в функции оптимизации.
- `ownSuccess`, `ciAcceptable`, `kAcceptable`, `bothAcceptable` разделены.
  `ALREADY_ACCEPTABLE` считается собственным успехом; `alreadyAcceptable` и
  `noChanges` сохранены отдельно. Итоговое число изменений может отличаться
  от числа выполненных исправлений.

**Единица анализа — исходная матрица.** Сначала среднее по seed внутри каждой
матрицы, затем равновесное агрегирование по матрицам. Так не создаётся ложного
увеличения независимой выборки. Групповые медианы/SD считаются по матричным
средним; в `per_matrix` — по seed. Выборочная SD использует N−1, при N<2 — NA.
Сохранены N матриц, число запусков, успехов, число матриц с успехом всех/хотя бы
одного seed, знаменатели относительных показателей. Неудачи входят в средние
и знаменатели. Начальные четыре категории учитываются по входам, не повторам.

Сводка содержит по каждой размерности/типу/методу средние и медианы CI, K,
снижений и времени; средние числа изменений, D и шагов; доли собственного
успеха, допустимого CI, K и обоих. Дополнительно есть категории начальной
согласованности и парные разности режимов GA (B−U) по матричным средним.
Нет утверждений о статистически доказанном превосходстве: N=4 на группу мало.

## Файлы и схема

```text
config/                    планы SMOKE/PILOT/REPORT/FULL и решение после пилота
inputs/<PROFILE>/          неизменяемые CSV + JSON метаданные/веса/возмущения
outputs/<PROFILE>/<plan>/   отдельные каталоги runId, включая WARMUP
summary/<PROFILE>/         manifest, plan, environment, schedule, таблицы, отчёт
summary/report.md          основной аналитический отчёт только REPORT
figures/<PROFILE>/         графики PNG 300 DPI / SVG + manifest источников
scripts/                   plot_results.py и версии Python-зависимостей
```

В каждом каталоге запуска: `original_matrix.csv`, итоговая CSV,
существующий CLI `result.json` с параметрами/историей и **`run.json`**:

```text
schemaVersion: 1
run: {profile, planSha256, phase, runId, caseId, size, type, initialCategory,
      configuration, mutationMode, seed, generationSeed, inputSha256, inputFile,
      resultFile, status, elapsedMillis, initialCi/K, finalCi/K, deltaCi/K,
      relativeCi/K, logDeviation, changedComparisons, steps, iterations,
      generations, fitnessEvaluations, ownSuccess, ciAcceptable, kAcceptable,
      bothAcceptable, alreadyAcceptable, noChanges, population, maxGenerations,
      maxIterations, targetCi/K, minimumComparison, maximumComparison,
      maxMutationAttempts}
environment: {javaVersion, javaVendor, vmName, osName, osVersion, osArch,
              availableProcessors, maxHeapBytes, cpuModel, physicalMemory}
profile: {... полный план ...}
```

Входные JSON сохраняют `generatorVersion`, параметры, seed, CI/K, SHA-256 и
сведения о латентной структуре. SHA относится к байтам CSV. `planSha256` —
SHA-256 канонической сериализации записи Java-плана (форматирование исходного
config не влияет). `REPORT.decision.json` дополнительно хранит хеши файлов
исходного и окончательного плана как байтов.

`summary/<PROFILE>`:

- `runs.csv/json` — одна строка/запись на измеряемый запуск;
- `warmup.json` — отдельная группа прогрева, не входит в `runs`;
- `inputs.csv/json` — один вход один раз;
- `per_matrix.csv/json` — сводка seed каждого входа/конфигурации;
- `aggregated.csv/json` — размерность × тип × конфигурация;
- `by_initial_category.csv/json` — дополнительное разбиение по начальным порогам;
- `overall.csv/json` — общая сводка (оба типа и все n с одинаковым весом входов);
- `paired_modes.csv/json` — парные различия B−U; формирует Python;
- `manifest.json`, `plan.json`, `plan.<sha>.json`, `environment.json`, `schedule.csv`;
- PILOT также содержит `resource_estimate.json`.

При повторном выполнении того же плана математические результаты воспроизводятся,
но время меняется и файлы результатов обновляются. Архив плана сохраняется с хешем,
выходы разных планов разнесены по хешу; итоговая сводка профиля указывает последний
выполненный план. Запись нескольких файлов не транзакционна; только COMPLETE
manifest разрешает их анализ. Для архивирования отдельных измерений времени
сохраните каталог профиля перед повтором.

## Графики

По типам A/B раздельно: итоговый CI, K, доли собственного/общего успеха,
время (логарифмическая ось), число изменённых сравнений, D и распределение K.
Boxplot показывает **матричные средние по seed** и каждую матрицу точкой;
при менее трёх независимых матрицах в группе не строится (SMOKE/PILOT).
Дополнительно общие: исходное распределение CI/K и динамика GA на заранее
выбранном `A_n06_m000`, seed 42 (в SMOKE — `A_n05_m000`).
Итого REPORT: 16 рисунков × PNG/SVG. В подписях и manifest указаны профиль,
N, источники и SHA таблиц. Скрипт проверяет полноту запусков, общность исходных
хешей, согласованность CSV/JSON и независимо пересчитывает иерархические средние.

## Проверки

JUnit использует только малый отдельный временный план: генерация размеров
3–10, свойства/шкала/seed, восстановление типа B по весам и возмущениям,
устойчивость D, нулевые знаменатели, планы/ID/общий вход, неудачи в статистике,
иерархические средние/медианы/SD, CSV/JSON, повторный запуск, обнаружение подмены
входа и сохранность эталонов воспроизведения. Тяжёлые профили в JUnit не запускаются.

Главные ограничения исследования и фактические численные выводы приведены
в [основном отчёте](summary/report.md). Интеграция с ранжированием альтернатив,
новые корректоры, качественные МПС, LaTeX и презентация на этапе 6 не добавлялись.
