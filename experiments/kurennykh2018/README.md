# Приближённое воспроизведение экспериментального исследования 2018 года

Этап 8 исследует только **существующий неизменённый косинусный корректор**.
Исходные матрицы здесь наши: они не представлены как авторские данные.
Основной результат: [аналитический отчёт REPORT](summary/REPORT/report.md),
[таблица сравнения](summary/REPORT/comparison_with_article.csv),
[параметры до запуска](PROTOCOL.md), [источники графиков](figures/REPORT/manifest.json).

## Анализ публикации

Оригинальный препринт: https://www.mathnet.ru/rus/ipmp2555,
DOI 10.20948/prepr-2018-196; локальный PDF `ipmp2555.pdf`.
Печатные страницы 12–13 и таблица 1 визуально сверены. Все 8 строк существующего
эталона совпадают с PDF, включая 67.7913 и 375.0551. Эталон не изменён; его
проверяемый SHA-256 —
`c291a1817a2c9ede3ce9b818f6b26c78cd1da7043f6da07dd8a8bc956fb0bfba`.

У авторов точно заданы C# 7.0/.NET Core 2.0, случайные положительные
обратносимметричные МПС размеров 3–10, выборка из 1000 матриц и формула (11)
полной суммы квадратов. **Не установлено N отдельно на каждую размерность.**
Не опубликованы генератор/распределение, входы/seed, способ весов и равенств,
полностью определённая автоматическая процедура, правило обработки выходов за
шкалу, отбор по исходному CI, лимит исправлений и измерительная среда.
Процентная вариация описана без точной формулы. Поэтому авторские проценты
ранговых изменений не вычисляются, точное воспроизведение не заявляется.

Подробное разделение правил авторов и наших операционных решений:
[заранее зафиксированный протокол](PROTOCOL.md) и разделы 2–6 отчёта.
Полные научные PDF в Git не добавляются.

## Зафиксированный и выполненный план

| Профиль | Размерности | Матриц на n | Всего измеряемых | Прогрев |
|---|---|---:|---:|---:|
| SMOKE | 3–10 | 5 | 40 | 80 |
| REPORT | 3–10 | 1000 | 8000 | 80 |

Оба профиля выполнены. Master seed **2018196**; DISCRETE_EXPERT равномерно
выбирает каждый верхний ген из 17 значений `{1/9,…,1/2,1,2,…,9}`.
Используется существующий `MatrixGenerator.seed(master,type,n,sample)`.
Профиль не участвует в seed: первые пять входов каждого n совпадают в профилях.
Никакого отбора по CI/K или исключения неудач. Совпадение двух матриц при
выборке с возвращением возможно и не ведёт к повторной генерации.

Косинусы: target CI=0.1, максимум 100 принятых исправлений, диапазон [1/9,9],
минимальное улучшение CI 1e-12, поддержка 0. Выходы за диапазон отклоняются,
не обрезаются и не округляются. Правила корректора и ядро не изменены.
Веса — прежний `PerronWeights`, а не ранжирование по внешней таблице альтернатив.
Ранги порядковые с 1, точные равенства double — по исходному индексу.

План и определения сохранены **до** запусков в `config/*.json` и `PROTOCOL.md`.
При запуске сохраняются `plan.initial.json`, `plan.json` и хеш; изменение плана
в том же корне запрещено, для нового плана нужен отдельный каталог. После
SMOKE сохранена оценка ресурсов `config/resource_assessment.json`: удвоенная
проекция по максимумам времени — 282.041 с. REPORT не сокращался и занял
84.226 с по manifest (около 84.279 с до возврата Java-задачи).

## Команды

Из корня проекта, JDK 17 / существующий Gradle Wrapper:

```bash
./gradlew clean build
./gradlew reproduceKurennykhSmoke
./gradlew reproduceKurennykh2018
./gradlew verifyKurennykh2018
./gradlew plotKurennykh2018
git diff --check
```

Задачи не зависят от `build`/`test`: тяжёлые эксперименты в JUnit не запускаются.
Первые три экспериментальные команды используют Java, без новых библиотек.
Графики используют существующую Python-среду matplotlib 3.10.8 / numpy 2.3.5:

```bash
python3 -m venv experiments/comparison/.venv
experiments/comparison/.venv/bin/python -m pip install -r experiments/comparison/scripts/requirements-lock.txt
```

Gradle выбирает этот Python, если он существует, иначе `python3`.
Повторное построение **без оптимизации**: `./gradlew plotKurennykh2018`.
Изолированный корень поддерживается вторым аргументом Java-задач, например
`./gradlew reproduceKurennykhSmoke --args="SMOKE build/demo/kurennykh2018"`.
Сначала скопируйте туда `config/SMOKE.json` и `PROTOCOL.md`; путь эталона остаётся
существующим read-only файлом проекта. Аудит SMOKE:
`./gradlew verifyKurennykh2018 --args="SMOKE"`.

После свежего клонирования массовых архивов может не быть: сначала выполните
`reproduceKurennykh2018`, затем `verifyKurennykh2018`, затем графики.
Сводные таблицы и графики REPORT сохранены в Git; сами архивы воспроизводимы.
Дополнительно `./gradlew compareKurennykh2018` перестраивает только таблицу
«авторы — наша реализация» из сохранённых агрегатов, без коррекции. Сохраняются
разность со знаком, её абсолютная величина и относительная разность. Для
ранговых счётчиков все разности NA из-за неизвестного авторского знаменателя.

## Метрики и статистика

Основная квадратичная ошибка — **E_full=Σ_iΣ_j(b_ij−a_ij)²**, формула (11).
Дополнительная E_upper считает только i<j. Основная вариация — заранее выбранная
**V_upper=100/m·Σ_i<j|b_ij−a_ij|/a_ij**, наша операционная формула.
V_changed усредняет только окончательно изменённые верхние гены, V_offdiagonal —
все i≠j. V_changed при нуле изменений — NA; N_defined сохранён отдельно.
Различные варианты не выбирались по близости к опубликованным числам.
Сохраняются ΔCI, K до/после, существующий D, статусы, признаки успеха/исходной
приемлемости, веса, лидеры, ранги и изменение позиции первоначально лучшего.

Четыре счётчика исправлений раздельны: iterations, acceptedCorrections,
uniqueTouchedComparisons, changedComparisons. В текущем API первые два равны
длине истории; повторные правки и возврат к исходной оценке означают, что
уникально затронутые и окончательно изменённые сравнения могут отличаться.

Группы по каждому n:

1. ALL — основная, все входы, включая все неудачи и первоначально приемлемые.
2. NEEDS_CORRECTION — только исходный CI>0.1, включая неудачи.
3. SUCCESSFUL_REQUIRED — успешно исправленные из предыдущей группы.

Для 17 метрик каждой группы сохранены N, N_defined, mean, median, sample SD,
min/max и 95% ДИ среднего по нормальному CLT-приближению с z=1.959963984540054.
N<2: SD/ДИ null; N<30: smallSample=true. При асимметричных хвостах и малых N
это приблизительные интервалы, не проверка значимости отличий от авторов.
Неудачи не исключены из ALL и NEEDS_CORRECTION. Авторские N и ДИ не выдумываются.

## Время и ограничения ресурсов

10 прогревов каждого n, отдельные seed master XOR 0x5741524d и sample 60000+round.
После прогрева измеряемые входы идут по n, затем sample по возрастанию;
один рабочий поток, измеряется только `correct()`. Внутренние вычисления CI/K
корректора входят во время, внешние веса/проверки, генерация и I/O — нет.
Это измерение одной среды, не JMH и не доказательство ускорения относительно C#.
Java/ОС/CPU/RAM/heap записаны в `environment.json`.

Лимиты: Java heap 512 МиБ, два архива суммарно ≤512 МиБ, 120 с на корректор,
7200 с на профиль. Исключение или исчерпание бюджета создаёт FAILED manifest
с ID/причиной; частичный запуск не считается REPORT. Алгоритмические статусы
MAX_ITERATIONS/NO_ADMISSIBLE_IMPROVEMENT являются результатами и учитываются.

## Компактные данные и проверка каждой матрицы

```text
config/                         фиксированные планы и оценка ресурсов
inputs/<PROFILE>/matrices.jsonl.gz
outputs/<PROFILE>/results.jsonl.gz
summary/<PROFILE>/              CSV/JSON статистика, планы, среда, manifest
figures/REPORT/                 8 PNG 300 DPI + 8 SVG + источники/хеши
scripts/                       построение отчёта/графиков, извлечение случая
```

Два REPORT-архива занимают около **18.14 МиБ**. Входной архив: одна JSON-строка
на случай, `{schemaVersion,id,size,sample,generationSeed,sha256,matrix}`.
Выходной: `{schemaVersion,run,matrix,initialPriorities,finalPriorities,
initialRanking,finalRanking,history}`. История — неизменённые поля
`CosineCorrectionResult.Change`; результат корректировки не дублируется в 8000
отдельных файлах. Массивы matrix полноценны, точность double сохранена.
Хеш каждой матрицы относится к её каноническому Java CSV: Double.toString,
запятая, LF. Хеши архивов в manifest относятся к сжатым байтам.

`inputs.csv` связывает ID/seed/хеш, номер строки архива и исходные CI/K.
`runs.csv` — одна строка на матрицу со всеми скалярными результатами и настройками.
`aggregated.csv/json` — размерность × группа × метрика; `groups.csv/json` —
числа успехов/неудач и знаменатели; `comparison_with_article.csv/json` — значения
авторов/наши, разности и ограничения сопоставимости. `warmup.json` отделён.
`manifest.json` COMPLETE содержит объём, хеши плана/протокола/эталона/архивов.
`runs.partial.csv` — только контрольная точка, исключённая из Git.

Аудитор повторно генерирует каждый исходный вход, сверяет его double/хеш,
пересчитывает CI/K и веса, воспроизводит сохранённые правки без оптимизации,
проверяет структуру/шкалу, ранги, метрики и полную статистику. Исходные seed
сравниваются как long без округления через double. Численные пересчёты допускают
10⁻¹¹·max(1,|a|,|b|); CSV/JSON агрегатов, хеши и исходные матрицы проверяются точно.

Для непосредственной проверки преподавателем можно извлечь любой ID:

```bash
python3 experiments/kurennykh2018/scripts/extract_case.py --id K2018_n03_m0000 --output-dir build/kurennykh-case
```

Будут получены исходная/итоговая CSV и два JSON с исходными метаданными,
весами и историей. При необходимости отдельный архив данных для сдачи:

```bash
mkdir -p build/distributions
zip -r build/distributions/kurennykh2018-data.zip experiments/kurennykh2018/config experiments/kurennykh2018/PROTOCOL.md experiments/kurennykh2018/inputs/REPORT experiments/kurennykh2018/outputs/REPORT experiments/kurennykh2018/summary/REPORT experiments/kurennykh2018/figures/REPORT -x '*/runs.partial.csv'
```

Это архив данных одного исследования, не финальный архив всей лабораторной.
GZIP-входы/выходы, временные файлы и SMOKE-графики исключены из Git. Код,
тесты, планы, протокол, README, основные сводки и графики REPORT сохраняются.

## Фактический итог и границы воспроизводимости

REPORT: 8000 матриц; 356 исходно приемлемых; 6718 успешно исправлены;
926 неудач (301 без допустимого улучшения, 625 по лимиту). Порог достигнут
у 7074/8000, среди нуждавшихся — 6718/7644. CI уменьшился у 7471
матрицы; у 173 нуждавшихся не было допустимого шага. Изменение ранга
первоначального лидера — 4531/8000.

Число исправлений и E_full растут с размерностью. Полная монотонность среднего
снижения CI не воспроизведена: при n=10 оно меньше, чем при n=9, на фоне
остановок по лимиту. Для n=3 после одной принятой правки триада согласована;
средние 1.507 авторских итерации несовместимы с нашим определением одной
принятой парной правки. Причина отличий счёта авторов не установлена.

**Точное численное воспроизведение таблицы 1 не достигнуто.** Состав исследования
воспроизведён на собственных данных, математическая работоспособность проверена,
качественные закономерности подтверждены частично, все численные расхождения
показаны без подгонки. Полные RQ1–RQ7, интервалы и ограничения — в отчёте REPORT.
Предыдущие результаты, эталоны и математические алгоритмы не изменялись.
