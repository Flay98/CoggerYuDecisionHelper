# Интеграционная процедура ранжирования

Этап 7 добавляет изолированный пакет `MCD.consistency.decision`. Он использует
полную положительную обратносимметричную МПС критериев и таблицу альтернатив.
Оригинальные `MCD.Main`, `Application`, `ChoiceMethod`, `Ranker`, `Matrix` и
`CSVReader` не изменены. Их исходные ограничения не исправлялись.

## Отличие от исходной программы

`Ranker.Survey()` получает только n−1 соседних предпочтений, а
`CoggerYuRankObjects()` формирует верхнетреугольные структуры и выполняет
собственную последовательность операций. `Ranker.EigenValues()` суммирует строки.
Эти структуры не используются в новом математическом пути.

Новая процедура — **нормализованный главный правый собственный вектор полной
МПС, нормализация значений критериев и взвешенная сумма**. Это стандартная
процедура извлечения приоритетов и явно выбранная интеграционная модель, а не
буквальная реализация Cogger–Yu. Нормализация и сумма не приписываются авторам
статей 2018/2026 годов. Веса здесь не называются оригинальными весами Cogger–Yu.

## Математика и численная реализация

Главный правый собственный вектор:

\[
Aw=\lambda_{\max}w,\qquad w_i>0,\qquad\sum_iw_i=1.
\]

Степенная итерация стартует с равномерных весов и вычисляет `Aw` через
log-sum-exp, затем вычитает логарифм суммы. Это сохраняет исходную матрицу и
избегает переполнения произведений/сумм. В каждой итерации проверяется разброс
`log((Aw)_i/w_i)` по всем компонентам, включая очень малые веса. Критерий
сходимости: разброс ≤`1e-12`, максимум 10000 проверок произведения `Aw`.
После перевода в double веса нормируются; проверяются положительность,
конечность, сумма и относительная невязка. Возвращаются вычисленное λ,
число проверок, параметры решателя и максимальная относительная невязка.

Если веса не представимы положительными double, λ не конечна, невязка не
подтверждена или лимит исчерпан, выдаётся `ArithmeticException`. Скрытой
замены весов геометрическими средними, строковыми суммами или нулевыми весами
нет. Индексы CI/K по-прежнему вычисляет существующий `ConsistencyMetrics`.

Нормализация MAX и MIN соответственно:

\[
u_{ij}=\frac{x_{ij}}{\sum_r x_{rj}},\qquad
u_{ij}=\frac{1/x_{ij}}{\sum_r(1/x_{rj})}.
\]

Вычислительно используются `x/max(x)` и `min(x)/x`, затем нормировка суммы:
общий множитель сокращается в формуле. Это предотвращает переполнение суммы
и обратных значений. Суммы — с компенсацией погрешности. Для экстремального
отношения значений нормализованная ячейка может округлиться к нулю в double;
искусственный положительный минимум не добавляется. Все исходные значения
строго положительны, поэтому деления на ноль нет.

Оценки и разности:

\[
S_i=\sum_jw_ju_{ij},\quad
\Delta w_j=w_j^{after}-w_j^{before},\quad
\Delta S_i=S_i^{after}-S_i^{before},\quad
\Delta r_i=r_i^{after}-r_i^{before}.
\]

Проверяются суммы каждого нормализованного столбца, весов и оценок (допуск
`1e-12`). Оценки сортируются по убыванию. Точно равные double-баллы сохраняют
порядок CSV; позиции последовательные 1, 2, …, без совместного места.
Погрешностный компаратор не применяется, поскольку он может нарушать
транзитивность. Отрицательное Δr — улучшение позиции; положительное ΔS
само по себе не гарантирует улучшения позиции.

## Входы и параметры

МПС: существующие `.csv`/`.json` через `MatrixFileReader` и
`PairwiseComparisonMatrix`. Таблица альтернатив: UTF-8 CSV, первый заголовок
строго `alternative`, далее минимум два уникальных непустых названия критериев.
Хотя бы одна альтернатива, уникальные названия, прямоугольность, положительные
конечные числа. Пробелы по краям удаляются, сравнение имён чувствительно к регистру.
Кавычки, запятые внутри имени, управляющие символы и многострочные ячейки
не поддерживаются; это явное ограничение небольшого CSV-диалекта.

`--directions max,min,max` соответствует столбцам заголовка по порядку.
Строка/столбец j МПС соответствует критерию j. Программа не сортирует критерии.
Из числовой МПС без названий нельзя автоматически проверить смысловое
соответствие: оно является контрактом входных данных. Опциональный
`--criterion-order speed,cost,accuracy` проверяет точное совпадение переданного
порядка с заголовком и отклоняет несовпадение, не переставляя столбцы.

Доступны все общие математические опции текущего CLI: seed, границы, target CI/K,
лимиты, population. По умолчанию seed=0, косинусы CI≤0.1/100 исправлений,
GA K<0.3/P1000/100 поколений/64 попытки. Без указанных границ косинусы не
вводят дополнительной шкалы, GA использует [1/7,7]. В демо явно задан [1/9,9].
Три корректировки всегда независимы: COSINE, GA_UPPER_ONLY, GA_BIDIRECTIONAL.
`--method`/`--mutation-mode` отклоняются в новом CLI: они противоречили бы
фиксированному четырёхсценарному сравнению. Один и тот же seed используется
в обоих режимах GA. Численные настройки решателя весов фиксированы и сохранены
в результате; в Java доступны через конструктор `PerronWeights`.

speed=`(9,7,6)/22`, cost=`(5,8,10)/23`, accuracy=`(82,90,95)/267`.

## Выходные файлы и схема

Основные восемь файлов:

```text
result.json
criterion_weights.csv
alternative_scores.csv
ranking_comparison.csv
original_matrix.csv
cosine_corrected.csv
genetic_upper_corrected.csv
genetic_bidirectional_corrected.csv
```

Ещё девять файлов: по три в `corrections/cosine`, `corrections/ga_upper_only`,
`corrections/ga_bidirectional`: `result.json`, `original_matrix.csv` и итоговая
CSV соответствующего корректора. Их схема — прежняя, без изменений.

Новый `result.json` версии 1 содержит:

```text
schemaVersion, indexBase, procedure, criterionOrder, tieRule
matrixFile, alternativesFile, matrixFileSha256, alternativesFileSha256
criteria[], alternatives[], directions[], alternativeValues[][]
matrix[][]                         исходная МПС, доступна старому MatrixFileReader
normalizedAlternatives[][]         один общий набор u_ij для всех сценариев
scenarios[]:
  id, status, changedComparisons
  matrix[][], matrixCsv, ci, k
  weights[], weightChanges[]
  weightComputation: {eigenvalue, iterations, maxRelativeResidual,
                      tolerance, maxIterations, method}
  normalizedAlternativesRef         #/normalizedAlternatives
  scores[], scoreChanges[], ranksByAlternative[], positionChanges[]
  ranking[]: {rank, alternativeIndex, alternative, score}
  winner
  correction: null или {algorithm, status, detail, initialMetrics, finalMetrics,
      parameters, iterations или generations, evaluatedIndividuals для GA,
      seed для GA, changedComparisons, elapsedMillis, historyFile}
```

Массивы весов идут в порядке критериев, баллов/позиций — в порядке альтернатив.
`ranking` отсортирован. Индексы объектов в JSON с нуля; позиции с единицы.
`historyFile` — относительный путь и JSON Pointer, например
`corrections/ga_upper_only/result.json#/results/genetic/history`.
Истории не дублируются в основном файле. Одна общая нормализованная таблица
используется по ссылке всеми сценариями: она зависит от альтернатив/направлений,
а не от весов. CSV чисел записываются без экранного округления, через double
представление Java. Время не используется для проверки воспроизводимости.

Перед записью проверяются все целевые пути против обоих входных файлов,
включая символические/жёсткие ссылки. Запись поверх входа запрещена. Экспорт
нескольких файлов не транзакционный; при ошибке он может быть неполным, CLI
возвращает ненулевой код. Код 2 — неверные аргументы/данные; 1 — I/O или
численная ошибка; 0 — успешный запуск, включая алгоритмические лимиты.
Остальные файлы существующего выходного каталога не удаляются.
